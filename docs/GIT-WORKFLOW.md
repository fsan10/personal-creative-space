# 提交、同步与回退

用户要求：每完成一个功能就提交一次；所有关键节点均应提交，尽量保留更多提交，方便以后回退。

## 每个工作节点

1. 将变更限制为一个可以解释和验证的目标。
2. 完成相应检查，并记录实际结果与仍需的外部连接。
3. 查看 diff，仅加入当前节点相关文件。
4. 使用 `feat`、`fix`、`docs`、`refactor`、`chore` 等前缀创建提交。
5. 推送提交；关键节点同时创建并推送编号标签。
6. 将节点与功能对应关系记入 `MILESTONES.md`。

标签示例：`checkpoint-001-foundation`、`checkpoint-002-markdown-editor`。实际编号按完成顺序递增。

## 回退某项功能

- 先确定提交范围、后续依赖和数据库变化。
- 用 `git revert <commit>` 创建撤销提交，必要时撤销一组相关提交。
- 执行对应检查，记录回退原因，再推送新的历史。
- 回退整站部署时，在保留的节点或版本上创建恢复分支并重新部署。

不使用强制推送或删除后续历史来完成常规回退。代码、数据库、媒体与第三方已经发布的文章分别处理。

## 远程暂时不可用

保留本地提交和标签，明确标记未推送。远程恢复后按原顺序推送，不合并成一个大提交。不得把远程同步失败报告成已同步。
